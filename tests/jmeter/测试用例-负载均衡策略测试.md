# 负载均衡策略切换与异构节点调度专项测试

## 一、测试目的

验证分布式判题集群的负载均衡策略切换功能和异构节点调度能力，确保：
1. 支持轮询（roundRobin）和最少任务（leastTasks）两种策略切换
2. 异构节点（不同配置的沙箱节点）能正确调度
3. 高并发场景下负载能均匀分布

## 二、测试环境

| 组件 | 配置 |
|-----|------|
| 沙箱节点数 | ≥3个（建议5个） |
| 节点类型 | 异构配置（不同maxConcurrency） |
| 测试工具 | JMeter 5.6 |
| 并发线程数 | 20-30线程 |

## 四、测试脚本说明

### 4.1 JMeter脚本结构

脚本包含三个测试场景：

1. **场景1：轮询策略测试**
   - 20线程，5次循环
   - 验证轮询分配的均匀性

2. **场景2：最少任务策略测试**
   - 20线程，5次循环
   - 验证任务优先分配到负载低的节点

3. **场景3：异构节点调度测试**
   - 30线程，3次循环
   - 验证不同配置节点的调度行为

### 4.2 参数配置

| 参数 | 默认值 | 说明 |
|-----|--------|------|
| HOST | localhost | 测试目标主机 |
| PORT | 8080 | 测试目标端口 |
| PROTOCOL | http | 协议类型 |
| THREADS | 20 | 并发线程数 |
| HETEROGENEOUS_THREADS | 30 | 异构测试线程数 |
| LOOP_COUNT | 5 | 循环次数 |
| RAMP_UP_SEC | 5 | 启动时间（秒） |

### 4.3 执行命令

```bash
# 轮询策略测试
jmeter -n -t loadbalance_strategy_test.jmx -JHOST=localhost -JPORT=8080 -JTHREADS=20 -JLOOP_COUNT=5

# 最少任务策略测试（需先切换策略）
curl -X POST http://localhost:8080/api/code/distributed/admin/strategy \
  -H "Content-Type: application/json" \
  -d '{"strategy": "leastTasks"}'

jmeter -n -t loadbalance_strategy_test.jmx -JHOST=localhost -JPORT=8080 -JTHREADS=20 -JLOOP_COUNT=5
```

## 五、结果分析指标

### 5.1 关键指标

| 指标 | 说明 | 参考标准 |
|-----|------|---------|
| 平均响应时间 | 提交请求平均耗时 | < 500ms |
| P95响应时间 | 95%请求耗时 | < 1000ms |
| 错误率 | 失败请求比例 | < 1% |
| 任务分布差异 | max(节点任务数) - min(节点任务数) | ≤ 3 |
| 吞吐量 | 每秒处理请求数 | ≥ 30 req/s |

### 5.2 策略对比

| 策略 | 适用场景 | 优势 |
|-----|---------|------|
| roundRobin | 节点性能相近 | 简单公平，实现简单 |
| leastTasks | 异构节点、性能差异大 | 智能分配，充分利用资源 |

## 七、测试注意事项

1. 测试前确保至少有3个健康的沙箱节点
2. 异构节点测试需配置不同的maxConcurrency元数据
3. 策略切换需通过API手动触发，不支持运行时动态切换（需重启生效）
4. 建议在低峰期执行测试，避免影响正常业务
