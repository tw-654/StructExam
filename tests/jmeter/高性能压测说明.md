# 沙箱节点高性能压测说明

## 一、目的

本测试脚本用于**突破业务层限流限制**，测试沙箱节点的真实处理能力。

## 二、脚本特点

| 特性 | 说明 |
|-----|------|
| **无线流延迟** | 移除了原脚本中的 `ConstantTimer(1000ms)` 延迟 |
| **高并发线程** | 默认50线程，可配置 |
| **多场景覆盖** | 包含代码提交和读接口两类场景 |
| **参数化配置** | 支持通过命令行参数自定义配置 |

## 三、测试场景

### 场景1：代码提交高并发压测
- POST /api/auth/login - 登录获取token
- POST /api/code/submit - 提交代码（无延迟）
- GET /api/code/result/{taskId} - 获取执行结果

### 场景2：读接口高并发压测
- GET /api/exam/list - 获取考试列表
- GET /api/exam/{id} - 获取考试详情
- GET /api/code/{exam}/{question} - 获取代码
- GET /api/code/distributed/nodes - 获取沙箱节点状态

## 四、运行方式

### 方式1：直接运行批处理（Windows）
```bash
cd tests/jmeter
run_high_perf_test.bat
```

### 方式2：命令行参数运行
```bash
# 默认配置：50线程，10次循环，10秒启动
jmeter -n -t sandbox_high_perf_test.jmx -l results/sandbox_high_perf.jtl -e -o results/sandbox_high_perf_report

# 自定义配置：100线程，20次循环
jmeter -n -t sandbox_high_perf_test.jmx ^
  -JTHREADS=100 ^
  -JLOOP_COUNT=20 ^
  -JRAMP_UP=5 ^
  -l results/sandbox_high_perf.jtl ^
  -e -o results/sandbox_high_perf_report
```

### 方式3：Docker容器运行（推荐）
```bash
docker exec structexam-jmeter sh -c '
  jmeter -n -t /tests/sandbox_high_perf_test.jmx \
    -JTHREADS=50 \
    -JLOOP_COUNT=10 \
    -JRAMP_UP=10 \
    -l /results/sandbox_high_perf.jtl \
    -e -o /results/sandbox_high_perf_report
'
```

## 五、参数说明

| 参数 | 默认值 | 说明 |
|-----|--------|------|
| THREADS | 50 | 并发线程数 |
| LOOP_COUNT | 10 | 每个线程循环次数 |
| RAMP_UP | 10 | 线程启动时间（秒） |
| HOST | gateway | 目标主机 |
| PORT | 8080 | 目标端口 |

## 七、注意事项

1. **测试环境**：建议在独立测试环境执行，避免影响生产业务
2. **资源准备**：确保沙箱节点有足够的CPU和内存资源
3. **测试用户**：需要提前创建足够的测试用户（jmeter_docker_01 ~ jmeter_docker_N）
4. **结果分析**：重点关注吞吐量和P95/P99响应时间

## 八、结果解读

测试完成后，查看 `results/sandbox_high_perf_report/index.html` 获取详细报告。

### 关键指标解读
- **吞吐量（Throughput）**：每秒处理的请求数，反映系统处理能力
- **P95/P99响应时间**：95%/99%的请求响应时间，反映系统稳定性
- **错误率（Error %）**：失败请求比例，反映系统可靠性
