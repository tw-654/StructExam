# 沙箱节点性能测试

## 一、测试目的

测试沙箱节点在不同任务负载下的性能表现，验证：
1. 50个任务的响应时间和稳定性
2. 100个任务的响应时间和稳定性  
3. 1000个任务的响应时间和稳定性
4. 沙箱节点的并发处理能力和资源利用率

## 二、测试环境

| 组件 | 配置 |
|-----|------|
| 沙箱节点数 | 3个（small/medium/large异构配置） |
| 测试工具 | JMeter 5.6 |
| 测试模式 | 单线程顺序提交（避免并发干扰） |
| 任务间隔 | 1秒（确保沙箱有时间处理） |

## 三、测试用例

### 3.1 场景1：50任务性能测试

| 参数 | 值 |
|------|-----|
| 线程数 | 1 |
| 循环次数 | 50 |
| 任务间隔 | 1秒 |
| 预期时间 | 约50秒完成 |
| 关键指标 | 平均响应时间、P95、P99、错误率 |

**测试思路**：
- 单线程顺序提交，避免并发干扰
- 每次提交间隔1秒，确保沙箱有时间处理
- 观察响应时间是否随任务数增加而变化
- 验证沙箱在轻负载下的稳定性

**测试思路**：

## 四、测试脚本说明

### 4.1 脚本结构

```
sandbox_performance_test.jmx
├── 场景1：50任务性能测试
│   ├── Once Only：登录获取token
│   ├── 循环50次
│   │   ├── POST /api/code/submit（提交代码）
│   │   ├── JSON提取器（提取taskId）
│   │   └── 延迟1秒
│   └── 响应时间统计
├── 场景2：100任务性能测试
│   └── 同上（循环100次）
└── 场景3：1000任务性能测试
    └── 同上（循环1000次）
```

### 4.2 关键配置

| 配置项 | 说明 |
|--------|------|
| HOST | 测试目标主机（默认localhost） |
| PORT | 测试目标端口（默认8080） |
| EXAM_ID | 考试ID（默认1） |
| QUESTION_ID | 题目ID（默认1） |
| 任务间隔 | 1秒（ConstantTimer） |
| 代码内容 | 动态生成（包含任务编号） |

### 4.3 执行命令

```bash
# 完整测试（50+100+1000任务）
docker exec structexam-jmeter sh -c 'jmeter -n -t /tests/sandbox_performance_test.jmx -l /results/sandbox_results.jtl -e -o /results/sandbox_report'

# 仅测试50任务
docker exec structexam-jmeter sh -c 'jmeter -n -t /tests/sandbox_performance_test.jmx -JHOST=localhost -JPORT=8080 -l /results/sandbox_50.jtl -e -o /results/sandbox_50_report'

# 仅测试100任务
docker exec structexam-jmeter sh -c 'jmeter -n -t /tests/sandbox_performance_test.jmx -JHOST=localhost -JPORT=8080 -l /results/sandbox_100.jtl -e -o /results/sandbox_100_report'

# 仅测试1000任务
docker exec structexam-jmeter sh -c 'jmeter -n -t /tests/sandbox_performance_test.jmx -JHOST=localhost -JPORT=8080 -l /results/sandbox_1000.jtl -e -o /results/sandbox_1000_report'
```

## 五、结果分析指标

### 5.1 关键性能指标

| 指标 | 说明 | 参考标准 |
|------|------|----------|
| 平均响应时间 | 提交请求平均耗时 | < 500ms（50/100任务），< 1000ms（1000任务） |
| P95响应时间 | 95%请求耗时 | < 800ms（50/100任务），< 1500ms（1000任务） |
| P99响应时间 | 99%请求耗时 | < 1000ms（50/100任务），< 2000ms（1000任务） |
| 错误率 | 失败请求比例 | < 1% |
| 吞吐量 | 每秒处理请求数 | ≥ 1 req/s（受1秒间隔限制） |

### 5.2 性能趋势分析

| 任务数 | 预期行为 | 异常表现 |
|--------|----------|----------|
| 50 | 响应时间稳定，无性能下降 | 响应时间突然增加，出现超时 |
| 100 | 响应时间略有增加，但仍稳定 | 错误率上升，内存占用异常 |
| 1000 | 响应时间可能增加，但不应失控 | 系统崩溃，OOM，大量失败 |

### 5.3 资源监控

在测试过程中监控以下指标：
- 沙箱节点CPU使用率
- 沙箱节点内存使用情况
- 沙箱节点磁盘I/O
- 沙箱节点网络流量
- Docker容器资源限制是否触发

## 六、测试注意事项

1. **测试隔离**：建议在独立环境中执行，避免影响正常业务
2. **资源清理**：测试完成后清理测试数据，避免数据库膨胀
3. **监控观察**：测试过程中实时监控沙箱节点资源使用情况
4. **时间安排**：1000任务测试需要约16分钟，建议在低峰期执行
5. **日志收集**：收集沙箱节点日志，分析潜在问题
6. **多次验证**：建议执行多次测试，验证结果的一致性

## 八、测试改进方向

1. **并发测试**：增加多线程并发测试，验证沙箱的并发处理能力
2. **压力测试**：逐步增加任务间隔，找到沙箱的性能极限
3. **长时间测试**：执行24小时持续测试，验证稳定性
4. **故障恢复**：在测试过程中模拟节点故障，验证恢复能力
5. **资源优化**：根据测试结果优化沙箱节点的资源配置
